1. Seeing What a Model Learned

Machine learning produces models that are hard to inspect directly: thousands or billions of numbers with no obvious meaning. Plots are how practitioners find out whether a model is learning, whether it is overfitting, which mistakes it makes, whether its probabilities can be trusted, what it bases its decisions on, and how the data look in the model’s eyes. This part is a guide to the standard plots of machine learning, with scikit-learn code for each. [1]

The plots of model performance, such as ROC and precision–recall curves, are covered in depth in the companion article Is 99% Accuracy Good?; here the focus is on reading them alongside the other diagnostic plots of a machine-learning project.

3. Learning Curves

A learning curve plots a model’s performance on its training data and on held-out validation data as the number of training examples grows. It answers one of the most practical questions in machine learning: would more data help, or do I need a different model?

How to read a learning curve
  • Both curves low and close: underfitting (high bias). Use a more flexible model or better features; more data will not help.
  • Training high, validation much lower: overfitting (high variance). More data, regularisation or a simpler model will help.
  • Validation still rising at the right edge: more data is likely to pay off.
# pip install scikit-learn matplotlib
import numpy as np
import matplotlib.pyplot as plt
from sklearn.datasets import make_classification
from sklearn.model_selection import learning_curve
from sklearn.tree import DecisionTreeClassifier

X, y = make_classification(n_samples=2000, n_features=20, n_informative=6, random_state=0)

fig, axes = plt.subplots(1, 2, figsize=(11, 4), sharey=True)
for ax, depth in zip(axes, [2, None]):                   # a shallow tree and an unlimited one
    sizes, train, val = learning_curve(DecisionTreeClassifier(max_depth=depth, random_state=0),
                                       X, y, cv=5, train_sizes=np.linspace(0.05, 1, 10))
    for scores, name, col in [(train, "training", "#0072B2"), (val, "validation", "#D55E00")]:
        m, s = scores.mean(1), scores.std(1)
        ax.plot(sizes, m, "o-", color=col, label=name)
        ax.fill_between(sizes, m - s, m + s, color=col, alpha=0.15)
    ax.set_title(f"Decision tree, max_depth={depth}")
    ax.set_xlabel("Number of training examples")
axes[0].set_ylabel("Accuracy")
axes[0].legend()
plt.tight_layout()
plt.show()

4. Loss Curves During Training

Models trained step by step, such as neural networks, are monitored with loss curves: the error on the training and validation data after each pass through the data (epoch). Their shape reveals a learning rate that is too low or too high, and the moment when the model starts to overfit.

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
# small synthetic problem: noisy targets, many features, few examples (easy to overfit)
X_train, X_val = rng.normal(size=(45, 40)), rng.normal(size=(200, 40))
w_true = np.zeros(40); w_true[:5] = 1
y_train = X_train @ w_true + rng.normal(0, 2, 45)
y_val = X_val @ w_true + rng.normal(0, 2, 200)

w = np.zeros(40)
train_loss, val_loss = [], []
for epoch in range(300):                                 # plain gradient descent on squared error
    grad = X_train.T @ (X_train @ w - y_train) / len(y_train)
    w -= 0.02 * grad
    train_loss.append(np.mean((X_train @ w - y_train) ** 2))
    val_loss.append(np.mean((X_val @ w - y_val) ** 2))

best = int(np.argmin(val_loss))
plt.figure(figsize=(7, 4))
plt.plot(train_loss, label="training loss")
plt.plot(val_loss, label="validation loss")
plt.axvline(best, color="gray", ls="--", label=f"best epoch ({best}): stop here")
plt.yscale("log")
plt.xlabel("Epoch")
plt.ylabel("Mean squared error")
plt.legend()
plt.tight_layout()
plt.show()

5. The Confusion Matrix

A confusion matrix tabulates a classifier’s predictions against the true classes. Drawn as a heatmap (Part 8), it shows at a glance which classes the model confuses. Normalising each row shows recall per class; normalising each column shows precision.

import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import ConfusionMatrixDisplay
from sklearn.model_selection import train_test_split

X, y = load_digits(return_X_y=True)                      # 8×8 images of handwritten digits (bundled)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.4, random_state=0)
model = LogisticRegression(max_iter=2000).fit(X_tr, y_tr)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))
ConfusionMatrixDisplay.from_estimator(model, X_te, y_te, ax=ax1, colorbar=False, cmap="Blues")
ax1.set_title("Counts")
ConfusionMatrixDisplay.from_estimator(model, X_te, y_te, ax=ax2, colorbar=False, cmap="Blues",
                                      normalize="true", values_format=".2f")   # each row sums to 1
ax2.set_title("Normalised by true class (recall on the diagonal)")
plt.tight_layout()
plt.show()

6. ROC and Precision–Recall Curves

Most classifiers output a score, and a threshold turns scores into decisions. The ROC curve, from the signal-detection theory developed for radar in the 1950s, [2] plots the true positive rate against the false positive rate for every threshold; the area under it (AUC) summarises how well the model ranks positives above negatives. [3] The precision–recall curve plots precision against recall, and is more informative when positives are rare. [4]

import matplotlib.pyplot as plt
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import RocCurveDisplay, PrecisionRecallDisplay
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=3000, weights=[0.9, 0.1], n_informative=4, random_state=1)  # 10% positives
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, random_state=0)
model = LogisticRegression().fit(X_tr, y_tr)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(11, 4.5))
RocCurveDisplay.from_estimator(model, X_te, y_te, ax=ax1)
ax1.plot([0, 1], [0, 1], "k--", lw=0.8)                  # chance
PrecisionRecallDisplay.from_estimator(model, X_te, y_te, ax=ax2)
ax2.axhline(y_te.mean(), color="k", ls="--", lw=0.8)     # chance = share of positives
plt.tight_layout()
plt.show()

7. Calibration Plots

When a model says “80% chance”, does the event happen about 80% of the time? A reliability diagram, long used for weather forecasts, [5] groups predictions by their stated probability and plots the observed frequency in each group. Alexandru Niculescu-Mizil and Rich Caruana showed in 2005 that common algorithms differ systematically: some push probabilities towards the extremes, others pull them towards the middle. [6]

import matplotlib.pyplot as plt
from sklearn.calibration import CalibrationDisplay
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.naive_bayes import GaussianNB
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=6000, n_features=20, n_informative=5, n_redundant=8, random_state=3)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, random_state=0)

fig, ax = plt.subplots(figsize=(6, 6))
for model, name in [(LogisticRegression(max_iter=1000), "Logistic regression"),
                    (GaussianNB(), "Naive Bayes"),
                    (RandomForestClassifier(random_state=0), "Random forest")]:
    model.fit(X_tr, y_tr)
    CalibrationDisplay.from_estimator(model, X_te, y_te, n_bins=10, name=name, ax=ax)
ax.set_title("Reliability diagram: on the diagonal = well calibrated")
plt.tight_layout()
plt.show()

8. Decision Boundaries

For a model with two input features, colouring the plane by the predicted class shows the model’s decision boundary. It is the most direct picture of what a model has learned, and of how its settings trade flexibility against stability.

import matplotlib.pyplot as plt
from sklearn.datasets import make_moons
from sklearn.inspection import DecisionBoundaryDisplay
from sklearn.neighbors import KNeighborsClassifier

X, y = make_moons(n_samples=300, noise=0.3, random_state=0)
fig, axes = plt.subplots(1, 3, figsize=(13, 4))
for ax, k in zip(axes, [1, 15, 100]):
    clf = KNeighborsClassifier(n_neighbors=k).fit(X, y)
    DecisionBoundaryDisplay.from_estimator(clf, X, response_method="predict_proba",
                                           cmap="RdBu", alpha=0.6, ax=ax)
    ax.scatter(X[:, 0], X[:, 1], c=y, cmap="RdBu", edgecolor="k", s=15)
    ax.set_title(f"k-nearest neighbours, k = {k}")
plt.tight_layout()
plt.show()

9. Maps of High-Dimensional Data

Real data often have dozens or thousands of features. To look at them, they are projected into two dimensions. Principal component analysis (PCA), going back to Karl Pearson in 1901, [7] finds the linear projection that keeps as much of the variance as possible; its axes are combinations of the original features. Non-linear methods such as t-SNE, published by Laurens van der Maaten and Geoffrey Hinton in 2008, [8] and UMAP (2018) [9] arrange points so that close neighbours stay close, which often reveals clusters beautifully.

import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.manifold import TSNE

X, y = load_digits(return_X_y=True)                      # 1,797 images, 64 pixels each
pca = PCA(n_components=2).fit_transform(X)
tsne = TSNE(n_components=2, perplexity=30, random_state=0).fit_transform(X)
# UMAP (pip install umap-learn): umap.UMAP().fit_transform(X)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))
for ax, Z, name in [(ax1, pca, "PCA: a linear projection"), (ax2, tsne, "t-SNE: preserves local neighbours")]:
    sc = ax.scatter(Z[:, 0], Z[:, 1], c=y, cmap="tab10", s=6)
    ax.set_title(name)
    ax.set_xticks([]); ax.set_yticks([])                  # the axes have no units
fig.colorbar(sc, ax=ax2, label="digit")
plt.tight_layout()
plt.show()
How to read a t-SNE or UMAP map
  • Points close together are similar; that part is reliable.
  • The sizes of clusters and the distances between clusters mean little; t-SNE in particular can make spread-out and tight clusters look the same size. [10]
  • The axes have no units or meaning, and the map changes with settings such as perplexity and with the random seed. Try several.
  • Apparent clusters can appear in random data; check them with other evidence.

10. Feature Importance and Explanations

Which inputs does a model rely on? Permutation importance, introduced with Leo Breiman’s random forests in 2001, [11] shuffles one feature at a time and measures how much performance drops. A partial dependence plot shows how the model’s average prediction changes as one feature varies. SHAP values, proposed by Scott Lundberg and Su-In Lee in 2017, [12] attribute each individual prediction to the features using Shapley values from game theory, and are often shown as a “beeswarm” of every case’s contributions.

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import make_friedman1
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.inspection import permutation_importance, PartialDependenceDisplay
from sklearn.model_selection import train_test_split

# Friedman's synthetic benchmark: y depends on x0–x4 only; x5–x9 are pure noise
X, y = make_friedman1(n_samples=2000, n_features=10, noise=1.0, random_state=0)
X = pd.DataFrame(X, columns=[f"x{i}" for i in range(10)])
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)
model = HistGradientBoostingRegressor(random_state=0).fit(X_tr, y_tr)

imp = permutation_importance(model, X_te, y_te, n_repeats=5, random_state=0)
order = np.argsort(imp.importances_mean)
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 4.5))
ax1.barh(X.columns[order], imp.importances_mean[order], xerr=imp.importances_std[order], color="#0072B2")
ax1.set_xlabel("Drop in R² when the feature is shuffled")
ax1.set_title("Permutation importance (x5–x9 are noise)")
PartialDependenceDisplay.from_estimator(model, X_te, ["x3"], ax=ax2)   # average effect of one feature
plt.tight_layout()
plt.show()

Importance is not causation. A feature can be important to a model because it is correlated with the real cause, and two correlated features can share or swap importance unpredictably. Importance plots describe the model, not the world.

11. Common Misreadings

  • Watching only the training loss. Without a validation curve, overfitting is invisible.
  • Reading accuracy instead of the confusion matrix. With imbalanced classes, a high accuracy can hide a class that is never predicted correctly.
  • Judging rare-event models by ROC AUC alone. Look at precision–recall as well.
  • Treating scores as probabilities. Check calibration before using a model’s outputs as risks.
  • Over-reading t-SNE and UMAP maps. Distances between clusters and cluster sizes are not reliable.
  • Treating feature importance as causal. It describes what the model uses, not what drives the outcome.

12. Legend and Record

Legend and Record: radar operators and weather forecasters

The legend: ROC curves and calibration plots were invented for machine learning.

The record: both are much older. The ROC curve comes from signal-detection theory, worked out in the early 1950s to describe how well radar operators, and later human observers, could distinguish a signal from noise; hence the name “receiver operating characteristic”. [2] Calibration was a central concern of weather forecasting long before machine learning: meteorologists checked whether it rained on about 30% of the days for which they forecast a 30% chance, and statisticians such as Morris DeGroot and Stephen Fienberg formalised the idea. [5]

A second record: t-SNE’s famous maps of handwritten digits look as if the clusters’ positions mean something. Martin Wattenberg, Fernanda Viégas and Ian Johnson showed with interactive examples how the same data can produce very different-looking maps as the settings change, and how random data can show clusters. [10]
