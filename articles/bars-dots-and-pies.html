Bars, Dots and Pies: Charts for Comparing Categories

An 8% difference can look threefold, five similar slices of a pie are almost impossible to rank, and the first bar chart was invented by accident. How to choose and read the charts that compare categories.

1. Comparing Categories

Many questions in analysis are comparisons between categories: which product sells most, which region is healthiest, which cause produces most defects, what share of energy comes from each source. The data are a few numbers, one per category, and the job of the chart is to make the comparison effortless. Part 1 showed that the eye judges positions and lengths best and angles and areas worst. [1] That one fact explains most of the advice in this part.

We will cover the bar chart and its relatives (grouped, stacked, diverging and Pareto charts), the dot plot and lollipop, and the much-debated pie chart, with Python code for each.

3. Bar Charts

A bar chart shows one number per category as the length of a bar. It is the workhorse of business and science because lengths on a common baseline are easy to compare. William Playfair drew the first one in 1786, showing Scotland’s imports and exports with seventeen countries for a single year, because he did not have the year-by-year figures he needed for a line chart. [2]

How to read (and make) a bar chart
  1. Check that the bars start at zero. If they do not, the lengths are misleading (Part 1).
  2. Read the order: sorted by value, alphabetical, or a natural order such as months?
  3. Compare lengths, not the positions of the bar tops on different axes.
  4. Ask what each bar is: a count, a total, a mean? A mean deserves an indication of uncertainty (Part 7).

This code makes a sorted horizontal bar chart with values written on the bars:

import numpy as np
import matplotlib.pyplot as plt

fruits = ["Apple", "Banana", "Cherry", "Grape", "Mango", "Orange", "Pear"]
votes = np.array([42, 67, 18, 25, 51, 39, 12])          # synthetic survey counts

order = np.argsort(votes)                               # sort so the ranking is easy to read
fig, ax = plt.subplots(figsize=(6, 4))
ax.barh(np.array(fruits)[order], votes[order], color="#0072B2")
ax.set_xlabel("Number of votes")
ax.set_title("Favourite fruit (horizontal bars, sorted)")
for y, v in enumerate(votes[order]):                    # label the bars directly
    ax.text(v + 1, y, str(v), va="center", fontsize=9)
ax.set_xlim(0, votes.max() * 1.12)                      # bars start at zero
ax.spines[["top", "right"]].set_visible(False)          # remove clutter
plt.tight_layout()
plt.show()

4. Grouped and Stacked Bars

When each category is split into subgroups, such as sales by region and quarter, there are three common layouts. Grouped bars place the subgroups side by side; stacked bars pile them on top of each other so that the bar’s height is the total; 100% stacked bars stretch every bar to the same height to show shares.

The key question is which segments share a baseline. In a grouped chart, all of them do. In a stacked chart only the bottom segment does, so it is hard to tell whether the middle segment is growing. Choose the layout for the comparison your reader most needs, and if you need several comparisons, draw several charts.

import numpy as np
import matplotlib.pyplot as plt

quarters = ["Q1", "Q2", "Q3", "Q4"]
sales = {                                               # synthetic sales by region
    "North": np.array([20, 24, 30, 28]),
    "South": np.array([15, 18, 16, 22]),
    "West":  np.array([10, 14, 19, 25]),
}
colours = ["#0072B2", "#E69F00", "#009E73"]
x = np.arange(len(quarters))

fig, (ax1, ax2, ax3) = plt.subplots(1, 3, figsize=(13, 4))

# 1. Grouped: compare regions within each quarter
width = 0.27
for i, (region, vals) in enumerate(sales.items()):
    ax1.bar(x + (i - 1) * width, vals, width, label=region, color=colours[i])
ax1.set_title("Grouped")

# 2. Stacked: see the total and its make-up
bottom = np.zeros(len(quarters))
for i, (region, vals) in enumerate(sales.items()):
    ax2.bar(x, vals, bottom=bottom, label=region, color=colours[i])
    bottom += vals
ax2.set_title("Stacked")

# 3. 100% stacked: compare shares, not sizes
total = sum(sales.values())
bottom = np.zeros(len(quarters))
for i, (region, vals) in enumerate(sales.items()):
    share = 100 * vals / total
    ax3.bar(x, share, bottom=bottom, label=region, color=colours[i])
    bottom += share
ax3.set_title("100% stacked")
ax3.set_ylabel("Share of sales (%)")

for ax in (ax1, ax2, ax3):
    ax.set_xticks(x, quarters)
ax1.set_ylabel("Sales (thousand units)")
ax1.legend()
plt.tight_layout()
plt.show()

5. Dot Plots and Lollipops

William Cleveland proposed the dot chart in 1984: each category gets a row, and its value is a dot on a common scale. [3] Because a dot encodes a value by its position rather than a length, the axis does not need to start at zero, so the dot plot can zoom in on small but important differences, such as life expectancies between 71 and 84 years. A lollipop chart is a hybrid: a thin line ending in a dot.

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
places = [f"Region {c}" for c in "ABCDEFGHIJKL"]
life = np.round(rng.uniform(71, 84, len(places)), 1)    # synthetic life expectancy (years)
order = np.argsort(life)
names, vals = np.array(places)[order], life[order]
y = np.arange(len(names))

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(11, 4.5), sharey=True)

# Cleveland dot plot: position on a common scale, no need to start at zero
ax1.plot(vals, y, "o", color="#0072B2")
ax1.grid(axis="y", alpha=0.3)
ax1.set_title("Dot plot")

# Lollipop: a thin stem from a baseline, lighter than a full bar
ax2.hlines(y, 70, vals, color="#999999", lw=1.5)
ax2.plot(vals, y, "o", color="#D55E00")
ax2.set_title("Lollipop (baseline 70)")

ax1.set_yticks(y, names)
for ax in (ax1, ax2):
    ax.set_xlabel("Life expectancy (years)")
    ax.set_xlim(70, 85)
plt.tight_layout()
plt.show()

6. Diverging Bars for Surveys

Survey questions often ask people to agree or disagree on a five-point scale, a Likert scale. The answers are ordered, with a natural middle. Richard Heiberger and Naomi Robbins recommended diverging stacked bars for such data: each bar is shifted so that the middle of the neutral category sits on a central line, with disagreement extending left and agreement right. [4]

Diverging bars are also used for any values with a meaningful centre, such as profits and losses, or changes above and below a target, with one colour for each direction.

import numpy as np
import matplotlib.pyplot as plt

questions = ["Easy to use", "Good value", "Fast delivery", "Helpful staff", "Would recommend"]
labels = ["Strongly disagree", "Disagree", "Neutral", "Agree", "Strongly agree"]
# synthetic percentages of respondents for each answer (rows add up to 100)
pct = np.array([[5, 10, 15, 45, 25],
                [15, 25, 20, 30, 10],
                [10, 15, 30, 30, 15],
                [3, 7, 10, 40, 40],
                [8, 12, 20, 35, 25]])
colours = ["#B2182B", "#EF8A62", "#CCCCCC", "#67A9CF", "#2166AC"]

# start each row so that the middle of "Neutral" sits at zero
left = -(pct[:, 0] + pct[:, 1] + pct[:, 2] / 2)
fig, ax = plt.subplots(figsize=(9, 3.8))
for j in range(5):
    ax.barh(questions, pct[:, j], left=left, color=colours[j], label=labels[j])
    left = left + pct[:, j]
ax.axvline(0, color="black", lw=0.8)
ax.set_xlabel("Percentage of respondents (negative to the left, positive to the right)")
ax.legend(ncol=5, bbox_to_anchor=(0.5, -0.25), loc="upper center", fontsize=8, frameon=False)
ax.invert_yaxis()                                       # first question at the top
plt.tight_layout()
plt.show()

7. Pareto Charts

In 1896 the economist Vilfredo Pareto observed that land and wealth in Italy and elsewhere were concentrated in a small fraction of the population. [5] The quality engineer Joseph Juran generalised the idea in his Quality Control Handbook of 1951: a few causes usually account for most of the problems, “the vital few and the trivial many”, and he named it after Pareto. [6] A Pareto chart sorts categories from largest to smallest and adds a line showing the cumulative percentage.

The “80/20 rule” is a tendency, not a law: in some data the top 20% of causes account for 95% of the effect, in others for barely half. The chart lets you see which is the case.

import numpy as np
import matplotlib.pyplot as plt

causes = ["Scratches", "Misalignment", "Loose screws", "Paint drips", "Cracks", "Wrong label", "Other"]
counts = np.array([142, 96, 51, 24, 15, 9, 13])        # synthetic defect counts

order = np.argsort(counts[:-1])[::-1]                   # largest first...
order = np.append(order, len(counts) - 1)               # ...but keep "Other" at the end
causes, counts = np.array(causes)[order], counts[order]
cum = 100 * np.cumsum(counts) / counts.sum()

fig, ax = plt.subplots(figsize=(8, 4.2))
ax.bar(causes, counts, color="#0072B2")
ax.set_ylabel("Number of defects")
ax.tick_params(axis="x", rotation=30)

ax2 = ax.twinx()                                        # second y-axis for the cumulative %
ax2.plot(causes, cum, color="#D55E00", marker="o")
ax2.axhline(80, color="gray", ls="--", lw=1)
ax2.set_ylim(0, 105)
ax2.set_ylabel("Cumulative percentage (%)")
ax.set_title("Pareto chart of defect causes")
plt.tight_layout()
plt.show()

8. Pie and Donut Charts

Playfair also invented the pie chart, in 1801. [2, 7] It shows parts of a whole as slices of a circle, so the reader must compare angles, arc lengths and areas, the encodings that Cleveland and McGill found least accurate. A donut chart is a pie with the centre removed, which hides the angles at the centre and leaves only arc lengths.

If you must use a pie chart
  • Use it only for parts of a single whole that add up to 100%.
  • Keep to two or three slices, or five at most; group the small ones into “Other”.
  • Start at 12 o’clock and order the slices by size, clockwise.
  • Label the slices directly, with percentages, and never use 3D, which distorts the slices nearest the viewer.
  • Do not compare several pies side by side; use stacked bars instead.
import matplotlib.pyplot as plt

labels = ["A", "B", "C", "D", "E"]
shares = [22, 21, 20, 19, 18]                           # close values: hard to rank in a pie
colours = ["#0072B2", "#E69F00", "#009E73", "#D55E00", "#CC79A7"]

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.pie(shares, labels=labels, colors=colours, startangle=90, counterclock=False,
        wedgeprops=dict(width=0.45, edgecolor="white"))  # width < 1 makes a donut
ax1.set_title("Donut chart: which is largest?")
ax2.bar(labels, shares, color=colours)
ax2.set_ylabel("Share (%)")
ax2.set_title("Bar chart: now it is easy")
plt.tight_layout()
plt.show()

9. Waffle Charts and Other Unit Charts

A waffle chart shows a part-to-whole split as a grid of 100 squares, one per percentage point. It is easier to read than a pie, because counting or estimating squares is easier than judging angles, and it suits audiences who find percentages abstract. Related unit charts and pictograms use one icon per person or per thousand people. Matplotlib has no built-in waffle chart, but drawing one takes only a few lines:

import numpy as np
import matplotlib.pyplot as plt

# A waffle (unit) chart: 100 squares, one per percentage point
groups = {"Renewables": 31, "Gas": 38, "Coal": 19, "Nuclear": 12}   # synthetic shares, sum to 100
colours = ["#009E73", "#56B4E9", "#555555", "#E69F00"]

cells = np.concatenate([[i] * n for i, n in enumerate(groups.values())])
fig, ax = plt.subplots(figsize=(5, 5))
for k, g in enumerate(cells):
    row, col = divmod(k, 10)
    ax.add_patch(plt.Rectangle((col, 9 - row), 0.9, 0.9, color=colours[g]))
handles = [plt.Rectangle((0, 0), 1, 1, color=c) for c in colours]
ax.legend(handles, [f"{k} ({v}%)" for k, v in groups.items()],
          loc="upper center", bbox_to_anchor=(0.5, -0.02), ncol=2, frameon=False)
ax.set_xlim(0, 10)
ax.set_ylim(0, 10)
ax.set_aspect("equal")
ax.axis("off")
ax.set_title("Electricity sources: each square is 1%")
plt.tight_layout()
plt.show()

10. Which One Should I Use?

You want to show… Good choice Avoid
Counts or totals for a few categoriesBar chart, sorted3D bars, truncated axes
Values for many categories, or small differencesDot plotBars starting above zero
Subgroups within categoriesGrouped bars (or small multiples)Stacks with many segments
Totals and their make-upStacked barsSeveral pies
Shares of a whole100% stacked bar, waffle, or a pie with 2–3 slicesPies with many similar slices
Agree–disagree survey answersDiverging stacked barsSeparate pies per question
Which causes matter mostPareto chartUnsorted bars

When categories are many and subgroups more than a few, consider small multiples: a grid of small charts with the same axes, one for each subgroup. Part 3 returns to this idea for time series. [8]

11. Common Misreadings

  • Bars that do not start at zero. The lengths, and so the visual differences, are exaggerated.
  • Reading a middle segment of a stacked bar as a trend. Its baseline moves with the segments below it.
  • Comparing slices across two pies. Pies of different totals cannot be compared slice by slice; the same angle may mean very different amounts.
  • Mistaking an average for a count. A bar showing a mean hides how much individual values vary; look for error bars or, better, the data points (Parts 5 and 7).
  • Over-reading the 80/20 rule. The Pareto principle describes a common pattern, not a guarantee.
  • Ignoring the denominator. A region with more cases may simply have more people; check whether bars show counts or rates.

12. Legend and Record

Legend and Record: are pie charts always bad?

The legend: pie charts are always wrong, and experts never use them.

The record: pies are poor for ranking or comparing similar values, as Cleveland and McGill’s experiments suggest. [1] But in 1991 Ian Spence and Stephan Lewandowsky found that for judging what proportion of the whole a part represents, pie charts were about as accurate as bar charts, and sometimes better, perhaps because the whole is always visible. [9] The designer Stephen Few, a strong critic, summarised the case against them in an essay titled “Save the pies for dessert”. [10] The fair conclusion: a pie with two or three slices showing parts of a whole is fine; a pie with ten similar slices is not.

A second legend: the bar chart was invented to show change over time. The record: Playfair’s first bar chart showed a single year, with a bar for each trading partner. He apologised for it, explaining that he lacked the data for a proper time series, and so invented the chart for comparing categories almost by accident. [2, 11]
